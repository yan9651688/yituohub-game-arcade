# 资源与缓存优化

本次把大图片、音轨从 HTML 内独立出来，缩短主文档下载与解析，允许媒体在页面代码更新后继续复用浏览器缓存。没有重编码图像或音乐，也没有修改战斗数值、物理、镜头和字幕时间轴。

## 无损资源拆分

`design/game-sources/` 保存优化前的六份应用 HTML 与 SHA-256 清单。`scripts/optimize_assets.py` 从这份显式基线生成 `public/games/*.html`、`public/film.html` 与 `/assets/media/`，不会覆盖输入来源或改首页、游戏库。新增原始游戏可放到该目录的 `games/` 后重跑。

提取了 35 张霓潮 WebP、12 张公路 JPEG、1 段 MP3，共 48 个文件、10,193,878 字节。每个文件的名称是完整 SHA-256，扩展名根据实际文件魔数确认；原声明与实际格式不一致时脚本拒绝处理。图片透明通道、音轨内容和 ID3 元数据保持原始字节。

可长期缓存的命名规则为：

```text
^/assets/media/[0-9a-f]{64}\.(webp|jpg|png|gif|mp3)$
```

以下单位均为字节。gzip 使用级别 9；表中“全部媒体”是假定相关媒体全部下载一次，不含 HTTP 头或共同依赖。

| 应用 | 原 HTML | 新 HTML | 原 HTML gzip | 新 HTML gzip | 新 HTML gzip + 全部相关媒体 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 霓潮 | 8,017,712 | 351,140 | 5,914,178 | 122,549 | 5,874,011 |
| 公路狂徒 | 378,585 | 211,941 | 191,701 | 75,248 | 200,749 |
| 千禧凝思 | 6,052,150 | 296,853 | 4,429,453 | 95,407 | 4,412,322 |

霓潮和影片的 HTML 减少约 95%，但完整冷加载的媒体总量仅小幅下降。原来的 gzip 已消除了大部分 base64 膨胀，因此不能把 HTML 缩小比例当作总下载量的缩小比例。公路缩略图继续保留原有按需展示与 `loading="lazy"`；全部图都下载时约增加 9 KB，未打开赛道图册时则省去这批图片的初始传输。

星陨前线、智械前线、雷霆战翼的 HTML 原 SHA-256 未改变。霓潮仍等待原有美术与动作 Promise 全部完成后启用开始按钮。影片仍等待字体、音轨和场景预热，保留 `?music=` 覆盖、原配乐显示名、播放、自由视角和重播；另增加始终可见的同源“返回游戏厅”。

## 冷、热缓存实测

使用 `scripts/tests/resource_benchmark.py`，在同一台机器、Chromium headless / SwiftShader、1440×900 视口下采样。网络限定 10 Mbps、40 ms 延迟；本地夹具采用 HTTP/1.1、预先生成的 gzip、HTML `no-cache`、媒体长期缓存及 MP3 Range。以下是单轮对照，不是互联网服务容量测试，也不是物理手机帧率测试。

“网络字节”来自 Chrome DevTools `Network.loadingFinished.encodedDataLength`，包含 HTTP 头。页面未变时 HTML 可以 304 重验证；浏览器 Resource Timing 的 `encodedBodySize` 仍可能显示缓存中原文件的体积，因此不用它冒充实际重新传输的字节。

| 场景 | 原版网络字节 | 优化版网络字节 | 原版可开始 | 优化版可开始 |
| --- | ---: | ---: | ---: | ---: |
| 霓潮首次访问 | 5,916,350 | 5,886,338 | 5.439 秒 | 5.080 秒 |
| 霓潮页面未变回访 | 606 | 606 | 0.553 秒 | 0.202 秒 |
| 霓潮仅代码更新后回访 | 5,914,954 | 123,318 | 5.274 秒 | 0.262 秒 |
| 公路首次访问 | 193,872 | 77,418 | 0.405 秒 | 0.215 秒 |
| 公路页面未变回访 | 606 | 606 | 0.816 秒 | 0.823 秒 |
| 公路仅代码更新后回访 | 192,467 | 76,012 | 0.813 秒 | 0.828 秒 |
| 影片首次访问 | 4,716,961 | 4,702,034 | 14.615 秒 | 10.147 秒 |
| 影片页面未变回访 | 202 | 606 | 11.555 秒 | 11.800 秒 |
| 影片仅代码更新后回访 | 4,429,841 | 96,181 | 14.006 秒 | 11.968 秒 |

代码更新场景使用只增加注释的 HTML 版本，媒体 URL 和游戏行为不变。优化后的霓潮两次回访中 35 张图均复用缓存，媒体网络字节为 0；影片两次回访的 MP3 网络字节为 0。影片额外的两个导航资源需重新验证，因此未变回访比原版多约 400 字节。

霓潮首次 HTML 响应结束从 4.989 秒缩短到 0.171 秒；影片从 4.043 秒缩短到 0.135 秒。冷访问仍需要下载大部分媒体，主要收益是更早完成文档与脚本解析，以及后续代码变更不再携带同一批媒体。影片预热仍有明显的客户端计算成本，热缓存不能消除它。

初次公路访问未发生外置 JPEG 网络请求，证明图册资源没有因为拆分而变成全量预加载。

## 缓存与服务器边界

- HTML、游戏目录 JSON 与版本信息使用 `no-cache`，让更新可及时重验证。
- 内容指纹媒体、图片、JS、CSS使用长缓存与 `immutable`；修改内容必须换 URL。发布构建先改写图片引用，再计算独立站点 JS/CSS 的指纹。
- Three.js 保持完整版本目录，升级库时同步升级目录名，避免父模块与相对导入缓存错配。
- 文本使用离线 gzip/Brotli，压缩结果在构建时生成。WebP、JPEG、MP3保持原字节，不再为它们做有损重编码；MP3需正确的 `audio/mpeg` 和字节 Range。
- HTTP/2减少多个独立媒体请求的连接开销；线上能力应结合实际 Nginx 模块、配置和运行结果验证。[缓存配置说明](nginx.md)

这五款游戏的战斗与电影画面在每位访客自己的浏览器中渲染。服务器主要提供静态资源。服务器吞吐、带宽、下载等待，与浏览器 GPU/CPU、游戏帧率应分别记录。

霓潮四张主要角色动作图每张为 1536×3584 RGBA，按宽×高×4估算单张约 22 MB；全部 35 张图片的基础 RGBA 像素约 98 MB，尚未包括画布副本、图集或 GPU 附加开销。这些像素尺寸未改变，不能声称纹理内存或战斗 FPS已经大幅下降。

若并发冷下载人数增加，出口带宽仍会被共享。压测应记录请求资源、响应体总量、并发、错误率、TTFB/下载时间和服务器 CPU/内存。100 个小静态请求的成功率不能等同于 100 人同时冷下载 6 MB 游戏、播放电影或在不同手机上保持相同帧率；本项目不承诺无限并发人数。

## 复现与验证

```sh
# 从显式原始来源生成媒体；不覆盖来源文件
python scripts/optimize_assets.py

# 固定网络条件下复现冷、热与代码更新回访
python scripts/tests/resource_benchmark.py

# 源文件的五游戏电脑/触屏启动与操作
python scripts/tests/game_smoke.py

# 构建后验证媒体哈希、游戏启动和影片退出
python scripts/build_release.py
python scripts/tests/integration_smoke.py --web-root dist
```

浏览器测试需要安装 Python Playwright 与其 Chromium。输出位于 `qa/`，属于本地证据，不提交到公开仓库。原站版本保留归档，用户原文件与原始基线保持不变；发布包只采集构建目录。


## 正式服务器受控并发测试

2026-10-01，在实际部署主机的独立候选目录上测试，主机为4 vCPU、约6GB内存，Nginx1.26.3。生成器与Nginx位于同一主机，使用真实可信TLS的HTTP/1.1新连接、gzip HTML/JSON、最大WebP以及MP3前64KiB Range混合请求。测试没有测量公网出口带宽、各地网络延迟或玩家设备帧率。

| 请求并发上限 | 总请求 | 错误 | 请求/秒 | p50毫秒 | p95毫秒 | nginx单核CPU百分比 | 结束RSS合计MiB |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 100 | 0 | 127.75 | 7.24 | 11.21 | 25.55 | 54.67 |
| 10 | 100 | 0 | 361.51 | 24.02 | 51.67 | 68.69 | 54.99 |
| 50 | 150 | 0 | 329.24 | 70.36 | 207.74 | 63.65 | 55.51 |
| 100 | 300 | 0 | 321.1 | 95.63 | 355.55 | 64.22 | 56.75 |

随后以100并发上限、100请求/秒持续30秒，共3000请求，0错误，p95为12.32毫秒，Nginx平均CPU为单核的20.77%（折合4核总预算约5.2%），结束时RSS合计65.48MiB。响应体合计575,362,191字节，均为本机流量。

突发测试时间较短，持续测试补充观察稳定负载。RSS是多个Nginx进程相加，共享页面可能重复计数，不是系统独占内存峰值。新TLS连接也包含生成器本身的调度成本；HTTP/2已通过实际curl协商确认，但本表刻意使用HTTP/1.1，不将两者混写。

原始聚合结果保存在[突发测试](benchmarks/server-burst.json)与[持续测试](benchmarks/server-sustained.json)，复现工具为`scripts/benchmark_static.py`。它限制100并发、最高200请求/秒与60秒持续时间，运行时须选择自己的服务器。

当前资源服务通过了这组受控负载，服务器不参与每位玩家的战斗计算。多人同时第一次下载时仍共享出口带宽，尤其霓潮的约5.9MB初载与影片配乐。出口合同带宽未取得可靠数值，不能据本机吞吐宣称支持某个固定真人数。若后续实际访问量上升，可根据带宽使用、下载时延、错误率再扩出口或增加静态资源分发；长期缓存与内容指纹已经支持这条扩展路线。
